## 1. 设计决定

| 决定 | 理由 |
|---|---|
| **没有 `error` 返回值**（原设计有） | 坏载荷按"跳过这条事件"处理，与 `readEvents` 的容错口径一致。返回一个永远为 nil 的错误，只是给调用方留一条走不到的分支 |
| `user_message` 开轮、其后 `assistant_turn` 填入 | 事件是扁平的，回合是配对出来的；配对规则写在一处，界面与上下文都按它来 |
| 同一轮多段正文用**空行连接** | 工具循环里模型可能说好几段（"我先看看"→"都通过了"）。后一段覆盖前一段就是丢内容 |
| 无 user 打头的回答**单独成轮**、`User` 留空 | 那是异常中断留下的残句，仍是模型说过的话；丢掉等于篡改历史 |
| 元信息 / 未知类型 / 坏载荷**一律跳过** | 老版本写的会话要能被新版本读出来；未知类型未来会越来越多 |
| `Tools` 累积到 Turn | 恢复时界面要能显示"这一轮用了什么"，也是将来导出/回看的唯一线索 |
