## 1. 一句话定义

**SyCode 是一个跑在终端里的 AI 编程代理**：它在当前工作目录中读写文件、执行命令、搜索代码，并通过多轮工具调用把"需求"变成"可运行的改动"。

## 2. 为什么要做

常见实现证明了一件事：一个**刻意保持精简**的终端 agent，只要工具契约稳、上下文管理合理、权限边界清晰，就足以覆盖日常工程工作。而同类产品普遍在三个方向上失控：工具数量膨胀、上下文无节制增长、对代码库的写权限过于宽松。

SyCode 的目标不是功能对齐某个商业产品，而是：

1. **可完全读懂**——任何人能在一天内读完核心链路（输入 → LLM → 工具 → 落盘）。
2. **可安全托付**——默认最小权限，危险操作必须显式确认。
3. **可被 agent 自行开发**——仓库本身按"AI 写代码、人写 prompt"的方式演进（见 WORKFLOW.md）。

## 3. 目标用户

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 个人开发者 | 在终端里改 bug、写脚本、批量重构 | 不想切 IDE，改完能直接跑测试 |
| 小团队 | 统一团队内的 agent 行为 | 可提交到仓库的项目级指令与权限白名单 |
| Agent 开发者 | 想理解/改造一个 coding agent 内核 | 结构清晰、每层可替换 |

## 4. 非目标（v0.1 明确不做）

- ❌ IDE 插件、Web UI、桌面 GUI
- ❌ 云端任务编排、远程 agent 执行、多租户
- ❌ 内置遥测/埋点上报——**即便是 opt-in 形态也不做**（本地日志除外，理由见 ADR-007）
- ❌ 一次性打包大量垂直领域工具（工具集保持 ≤ 10）
- ❌ 自建模型推理、本地模型加载

## 5. v0.1 功能需求

需求编号规则：`F-<模块>-<序号>`。**每条都必须可验收**，不可验收的需求不进 v0.1。

### 5.1 CLI 与会话入口

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-CLI-1 | `sycode` 无参数启动交互式 REPL | 在任意目录执行后进入 TUI，显示 banner、模型名、当前目录 |
| F-CLI-2 | `sycode --version` / `sycode version` | 输出版本号与 commit，退出码 0 |
| F-CLI-3 | `sycode --cwd <path>` 指定工作目录 | 之后所有相对路径、权限判断均以该目录为根 |
| F-CLI-4 | REPL 内 `/exit`、`Ctrl+C`（一次中断当前回合、两次退出） | 退出时正常落盘会话，无残留 goroutine（`go test -race` 无泄漏报告） |
| F-CLI-5 | `sycode run "<prompt>"` headless 单回合 | 非交互执行一次，输出纯文本；`--format json` 输出结构化结果 |

### 5.2 模型接入

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-LLM-1 | 支持 OpenAI 兼容协议（v0.1 唯一实现） | 可通过配置指向 OpenAI / DeepSeek / Kimi / 本地 vLLM，同一份代码无需改动 |
| F-LLM-2 | 流式输出 | 文本增量渲染，首 token 到屏幕 < 1s（本地网络正常前提下） |
| F-LLM-3 | 模型元数据注册表 | 每个模型登记 `context_window`、是否支持 thinking；未知模型给出警告而非崩溃 |
| F-LLM-4 | `/model` 切换模型 | 切换后下一回合生效，会话历史保留，当前上下文占用重新计算 |
| F-LLM-5 | 失败重试 | 429/5xx/网络错误按指数退避重试 3 次，UI 显示第几次重试；4xx 参数错误不重试 |
| F-LLM-6 | 中断 | 流式中 `Esc` 中断，已产出的文本保留，不写半截工具调用 |

### 5.3 工具层

| 编号 | 工具 | 关键约束 | 验收标准 |
|---|---|---|---|
| F-TOOL-1 | `read_file` | 二进制拒绝；单次默认 ≤ 1000 行；超长行截断 | 返回内容带行号，`offset/limit` 正确分页 |
| F-TOOL-2 | `write_file` | 自动建父目录；整体覆盖 | 覆盖前后产生 diff 并渲染到 UI |
| F-TOOL-3 | `edit_file` | 精确字符串替换（v0.1）；不唯一匹配时报错并列出候选行号 | 匹配 0 处或多处必须失败，禁止"猜着改" |
| F-TOOL-4 | `glob` | 支持 `**` 通配；结果上限 500 条 | 忽略 `.git/`，遵循 `.gitignore` |
| F-TOOL-5 | `grep` | 正则搜索；可按 `include` 过滤后缀 | 输出 `path:line:content`，超 200 命中时提示收窄 |
| F-TOOL-6 | `bash` | 超时默认 120s；输出超限落盘为 artifact 文件 | 危险命令（`rm -rf`、`git reset --hard`、`curl \| sh`）必须二次确认 |
| F-TOOL-7 | 工具注册表 | 统一 schema 导出给 provider | 新增工具只需 1 个文件 + 1 行注册，不改 llm 层 |

### 5.4 权限与安全

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-SEC-1 | 三态权限：`Denied` / `Pending` / `Granted` | 工作区内读取 Granted；任何写入 Pending；系统目录 Denied |
| F-SEC-2 | 交互式批准弹窗 | 展示工具名、目标路径、diff 预览、`允许一次 / 本会话总是允许 / 拒绝` |
| F-SEC-3 | `.gitignore` 感知 | 被忽略的路径读写均 Denied，并说明原因 |
| F-SEC-4 | 路径穿越防护 | `../../etc/passwd` 类输入被解析后仍按真实路径判定，不得绕过 |
| F-SEC-5 | 密钥不落盘 | 日志、会话 transcript、屏幕输出中均不出现 API key 明文 |

### 5.5 会话与上下文

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-SES-1 | 会话事件溯源落盘（JSONL） | 每个回合结束即可在 `~/.sycode/sessions/` 找到完整事件 |
| F-SES-2 | 启动时按工作目录恢复最近会话 | 同一目录二次启动，历史可见；`--new` 强制新会话 |
| F-SES-3 | `/context` 显示上下文占用 | 显示已用 token / 预算 / 百分比进度条 |
| F-SES-4 | `/clear` 清空当前上下文但保留会话文件 | 清空后可继续对话，旧事件仍在文件中 |

> 上下文**压缩（compaction）**、**持久记忆（memory）**与**子代理（subagent）**都是 v0.1 之后的专题，见 ROADMAP 第 6 节"待设计"，本 PRD 不预设方案。memory 之所以并入上下文专题而非单独做：它本质是"跨会话的上下文注入"，预算、裁剪、与 `AGENTS.md` 的优先级关系都必须在同一套规则里定。

## 6. 非功能需求

| 维度 | 要求 |
|---|---|
| 启动性能 | 冷启动到可输入 < 300ms（不含 provider 握手） |
| 平台 | Windows 10+ / macOS 12+ / Linux（amd64 + arm64），CI 三平台跑测试 |
| 单二进制 | `go build` 产出单文件，无运行时依赖（除用户 shell） |
| 可观测 | `SYCODE_LOG_LEVEL=debug` 输出结构化日志到 `~/.sycode/logs/` |
| 内存 | 单会话常驻 < 200MB（不含工具输出 artifact） |
| 离线 | 除模型 API 外无任何外部依赖；无遥测 |
| 磁盘 | `~/.sycode/` 自我回收，不靠用户手动清理：artifact 7 天、日志与会话 14 天、输入历史 1000 条上限 |

## 7. 成功指标（自用 + 小范围试用）

1. 一个真实小任务（修 bug + 跑测试）能在 1 次会话内完成，无需人工复制粘贴代码。
2. 权限弹窗误报率低：日常只读操作零打扰。
3. 新贡献者（人或 agent）能在 **2 小时内**基于 ARCHITECTURE.md 提交第一个可合并的 PR。

## 8. 风险与未决问题

| 风险 | 影响 | 缓解 |
|---|---|---|
| 终端 PATH 被裁剪，`go` 不可见 | 开发/CI 脚本误判为未安装 | 统一 `source scripts/env.sh`；工具链实际在 `D:\Apps\Go`（go1.26.3） |
| 默认模块代理不可达 | 依赖无法拉取 | env.sh 固定 `GOPROXY=https://goproxy.cn,direct` |
| Windows 下 shell 语义差异（bash 工具） | 命令执行行为不一致 | ADR-006 明确 shell 选择顺序，CI 覆盖 Windows |
| 流式 + TUI 并发状态竞争 | 偶发 UI 错乱/崩溃 | 单写者原则 + `-race` 常态化 |
| 上下文窗口不可控增长 | 长会话失效 | v0.1 只做监测与提示，压缩方案单独立项 |
| 模型行为差异（工具调用质量） | 体验波动 | 系统提示词与工具描述集中管理，按 provider 可覆写 |
